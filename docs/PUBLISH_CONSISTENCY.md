# 发行一致性说明

## 发布顺序

发布请求只能引用服务配置的 staging 根目录下、已受保护的作业。接口拒绝任意本机路径、对象存储 URL、凭据和未登记字段。

上传前服务校验 v1 manifest、项目仓库绑定、数字版本与标签、40 位 revision、发行状态、`SHA256SUMS`、文件大小及各文件 SHA256。manifest、摘要清单和资产必须一致。路径遍历、重复名称、缺失文件、未声明文件和摘要不匹配都会在更新 latest 指针前失败。

版本对象按 `releases/{project}/vX.Y.Z/` 写入并使用条件创建。每个对象写入后都通过 HEAD 核对摘要和长度。相同版本与摘要可幂等重试；同一项目和版本出现不同发行摘要时拒绝。

所有不可变对象验证成功后，服务才条件更新 `{prefix}/{project}/{channel}/latest.json`。已有指针使用 ETag 条件写入，首次创建使用仅创建条件。响应指针引用已存在的 immutable manifest。

## 回滚

回滚要求 `release.storage.rollback` 权限、项目范围、超级管理员身份、明确二次确认和原因。目标必须属于同一项目和渠道，且其不可变 manifest 已存在并通过摘要校验。

回滚只更新 latest 指针，不覆盖或删除发行对象。审计记录保留前后指针、操作者、request ID、时间、原因、对象键和摘要。同一 request ID 仅能由操作、项目、渠道、操作者和规范化请求均相同的重试复用。

## 原子性边界

SQLite 与 S3 兼容对象存储之间没有跨系统事务。读取方可能短暂看到尚未提交至本地数据库的新指针。如果最终 HEAD 检查或数据库提交失败，服务会通过条件请求恢复先前指针，或移除本次首次创建的指针。补偿也失败时返回 `503 pointer_reconciliation_required` 并记录待处理状态，管理员需核对数据库指针、审计记录和对象存储 latest。

当前修改操作由单进程锁串行化。多实例部署前需要共享事务仓库、项目与渠道级分布式锁，以及持久化恢复任务。

## 验证边界

本地单元测试覆盖摘要校验、路径遍历防护、冲突、幂等、指针补偿、回滚及凭据隔离。它们不证明真实对象存储授权、匿名 HTTPS 可读性、生产数据迁移或外部更新器行为；这些验收需分别取得证据。
