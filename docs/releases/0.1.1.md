# Fuwu 0.1.1

- Add a permission-protected system update page with stable-release discovery, explicit update confirmation, durable job status polling, and job restoration after a page refresh.
- Publish a complete update bundle from the exact tagged source commit, including the backend, locked dependencies, and built frontend assets. `SHA256SUMS` covers both the source archive and update bundle.
- Validate the fixed GitHub release contract, asset sizes and checksums, archive paths, and embedded release manifest before installation.
- Run installation in a detached systemd worker, create a consistent SQLite backup, prepare an immutable version directory, and atomically switch the active release link.
- Restart `fuwu-server.service` and verify the reported version through `/healthz`. If startup or health verification fails after switching, restore the previous release and verify its health.

The host must be bootstrapped with protected version directories, a `current` release link, a frontend static directory routed through that link, and the `fuwu-server.service` unit before online installation is enabled. The updater leaves environment files, databases, staging data, logs, and secrets outside version bundles. This release does not add a non-backward-compatible database migration; such migrations require a separate migration and rollback design.
