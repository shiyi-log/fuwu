# Fuwu 0.1.0

- Allow email addresses as account usernames while keeping existing username accounts compatible.
- Add email verification codes for self-service password recovery. Codes expire after 10 minutes, are limited to three sends per email per hour, allow at most five failed attempts, and revoke all existing sessions after a successful reset.
- Store only an HMAC digest of each code and require HTTPS for password recovery outside loopback requests.
- Configure SMTP through deployment environment variables; do not place mail credentials in source, the database, or API responses.
- Add a host-only command to change the active superadmin username to a confirmed email address when recovering an existing account.
- Add `scripts/reset_password.sh` and the `reset-password` account command for host operators to reset an active account through two hidden password prompts. Require an existing initialized database, revoke sessions and reset codes, and record an audit event.

Account initialization creates the new recovery tables idempotently. Existing usernames, password hashes, and release records remain unchanged.

- Integrate the core module split while preserving existing public imports and release contracts.
- Reject proxy requests that previously inherited the direct-loopback HTTPS exception; trusted proxies must overwrite a single protocol header.
- Forward both public download paths through Nginx, stream asset responses, and accept upstream HTTPS only from explicitly allowed proxy addresses.
- Require a non-default deployment secret, inject SMTP settings into Compose, and bind published ports to loopback by default.
- Prevent duplicate password-reset submissions and ignore asynchronous UI results after leaving the page.
- Run Fuwu component tests and product-version consistency checks in CI.

Deployment requires a trusted HTTPS entry point and a random `DJANGO_SECRET_KEY`. SMTP credentials are supplied by the operator; email delivery must be validated independently before treating self-service recovery as operational. Roll back the application without deleting the additive recovery tables or changing published release pointers.

Source archives exclude generated frontend bundles. Build the frontend from the selected source commit (or use the frontend Dockerfile) before deploying it.
